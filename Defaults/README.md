# Packaged rotations

Definitions in this folder are addon data and read-only in game. They always appear in the rotation list, including disabled and inapplicable definitions. Enable preferences live in the profile's `rotationLibrary.preferences`. Clone creates an independent per-spec custom body in the existing SavedVariables rotation store; `rotationLibrary.origins` keeps its manifest, source revision, baseline and step origins. The default is never copied into that editable store automatically. Editing a clone cannot alter its source. Changing profiles rebinds preferences; no source pack overwrites saved rotations or the user's existing fallback.

The first pack is **TBC Shaman early leveling, levels 1–19**, a preview of the authoring/runtime path, not the completed all-class corpus. It uses independent optional highlights for missing weapon imbue and Lightning Shield, plus a Lightning Bolt opener, Earth Shock and a stationary ranged Lightning Bolt filler in the sequential priority. Missing upkeep never blocks a damage recommendation. Known-spell guards skip untrained abilities. Actions use the existing rank expansion/highlighting path; the portable numeric Lightning Shield predicate opts into readable localized rank-family matching. Existing temporary weapon enchants are respected. Spell usability/resources/range and actual action-bar availability are checked by the engine; this pack does not cast actions automatically.

This deliberately modest starter does not encode healing/interrupt overrides, consumables, totem placement, movement-aware openers, enemy time-to-live, Flame Shock weaving, automatic selection of the five-second-rule refresh window (upkeep remains an optional reminder), or later talents/spec rotations. It stops applying at level 20. Revision3 adds the requested ranged filler: native Attack range is preferred; if unavailable, a conservative LibRangeCheck five-yard interval is used. An uncertain interval never becomes a positive beyond-melee match. Normal spell range/usability still applies to the suggested Bolt. This ranged adaptation is RM behavior requested during live testing, rather than a claim that the source guide prescribes that exact decision graph. Do not extrapolate it to max level, dungeons, PvP or other editions. Those remain separate sourced corpus work. Source review and offline scenarios do not establish live recommendation quality or optimal DPS. In-game leveling/rank/highlight verification remains outstanding.

Its guidance was checked against [Icy Veins' original Enhancement leveling guide](https://www.icy-veins.com/tbc-classic/enhancement-shaman-leveling-guide) on 2026-10-17 (page revision 2026-01-12). The implementation adapts the guide's upkeep, pull and shock priorities into a small starter. Spell identity/rank references are recorded in the manifest. No guide prose or complete guide was reproduced. Rank 1 Lightning Shield is learned at level 8; rank 2 at 16. Exact learned state, rather than an assumed training level, controls whether an action can appear.

Authoring requirements: version 1 envelope, stable pack ID/revision and step IDs, explicit edition/action context, localized name/description keys, provenance and independent condition tables. Class/spec may be omitted for shared packs. Unknown condition/schema/edition data remains visible but unavailable for execution. Roles, intent and ruleset selectors currently remain reference-only until their context providers are implemented; do not silently treat them as universal. Retail/Forever defaults remain reference-only under the current restricted-data policy.

Run `python3 tools/check`. `tests/defaults.lua` loads real predicates and the shipped pack, checks structural resolution/localization/source scope, and exercises untrained abilities, upkeep, both shield ranks, combat and friendly targets. This is the starting fixture for a broader corpus scenario suite. The shared native roster/editor now shows packaged and custom definitions with the same read-only/editable card layout.

`tests/default_corpus.lua` automatically loads every direct `Defaults/` Lua entry in the TOC across five synthetic client families and thirteen class tokens. It checks source/review metadata, English name/description coverage, schema resolution on matching editions/classes, nested stable IDs, definition validation, visibility, read-only isolation, enable/disable and runtime exclusion at sampled level/spec/build/context boundaries. Invalid-manifest probes verify the guard rejects missing translations/sources, invalid dates and incomplete conditions/branches. It never evaluates combat conditions. This is an authoring/selection gate; it adds neither class coverage nor gameplay scenarios, and synthetic declarations do not certify live APIs or recommendation quality. Add pack-specific behavioral scenarios alongside new packs.

Default, clone and import validation share effective global/profile item-set references, with a nonnil profile entry taking precedence. Dependency additions/removals and registered schema changes refresh catalog validation without reload; unchanged lookups do not revalidate all packaged graphs. A structurally valid packaged source remains visible with diagnostics if a changed condition schema makes it invalid. Runtime eligibility keeps that source inert; custom saves still use strict current-schema validation. Extensions should change schemas through RegisterCondition/UnregisterCondition rather than silently mutating nested fields.

The second pack is **TBC Mage early Frost leveling, levels1–19**, revision1. Its original priority data adapts [Icy Veins' single-target Frost leveling guide](https://www.icy-veins.com/tbc-classic/frost-single-target-mage-leveling-guide) (reviewed2026-10-18, guide revision2026-01-12): optional missing Intellect/armor, then filler preferences selected by trained early ranks. Base action families use the existing ranked lookup: the highest learned, mapped and ready candidate is preferred; the engine may fall back to a lower rank before changing families. Mutually exclusive training-dependent branches avoid repeated filler entries in multi-step previews. Untrained/unusable/out-of-range preferred spells can fall through; this is an RM adaptation, not a damage calculation. Openers require a stationary, living hostile unengaged target; an explicit out-of-combat Stop separates combat priorities. Upkeep accepts other casters and localized higher ranks.

This Frost-oriented preview omits kiting, crowd control, emergency shields, finishers, wand optimization, consumables, Fire/Arcane talent-specific priorities and levels20+. It does not establish optimal DPS. `tests/defaults_mage.lua` runs real predicates/readiness through early/late training, availability, movement/target state and independent upkeep, plus multi-step traversal through the real sequence executor, spell catalog and main rank expansion. No guide prose or complete guide was copied. Broader class/spec/role/edition defaults and client verification remain pending.

Revision5 supersedes revision4's optional Attack reminder. Weapon Attack is now a universal implicit final sequential fallback: after no earlier action qualifies, in living hostile melee combat with inactive autoattack and all normal action checks satisfied. The engine never inserts a saved step or operates a button. A matching Stop ends lower priorities; the fallback remains eligible unless explicitly suppressed. An unavailable Stop guard suppresses both. Optional upkeep remains independent. Explicit same-action known checks were removed from this pack because every spell action now requires learned state, resources, cooldown and range automatically. Cross-action checks remain available. Existing clones retain their authored steps; compare against the current source to remove an older optional Attack if desired. Actual Attack-button identification/highlighting remains a client test.

Revision6 adds a Stop-if-not-in-combat boundary immediately after the pull opener. Combat priorities below it no longer repeat the player-combat predicate. Stop permits the implicit melee fallback unless its new suppression option is enabled; the fallback still independently requires player combat, so it cannot propose a new pull after the pre-combat boundary. Existing clones retain their prior authored conditions.

Revision7 replaces the two explicit Lightning Shield rank checks with one `BUFF` predicate using `spell=324, anyrank=true`. Exact numeric-ID aura checks remain the default elsewhere. The opt-in compares readable localized names after the exact-ID check, so it can recognize a higher rank without English literals or enumerating all ranks. Unreadable metadata or aura identity stays unavailable, including under NOT. This does not expand the pack beyond levels1–19 or certify later-level recommendations.
