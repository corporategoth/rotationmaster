# Translations

Ten locales: deDE, esES, esMX, frFR, itIT, koKR, ptBR, ruRU, zhCN, zhTW. The game client's locale is used; a language picker was
built and then removed on purpose.

- English is the key. Locale files are generated by `tools/locales.py` and carry `-- en:` source comments; never edit them by
  hand. Use `tools/translation_status.py`, `translation_todo.py` and `translation_apply.py` (workflow:
  `docs/translators/README.md`). Glossary and per-language register: `docs/translators/glossary.md` and `style.md`.
- **AI-assisted translation is allowed**, as a draft: validation (placeholders, color codes, line breaks, length, identical-to-
  English) is mandatory; give the model the glossary and style guide; small batches; no personal data; state in the commit
  message whether a native speaker reviewed it, and do not claim a review that did not happen. Do not guess game terms.
- Registers (measured): German formal Sie; French vous; Spanish (both) informal tú; Italian tu; Portuguese você; Russian Вы;
  Korean polite -합니다/-세요; Chinese 你. Details in `style.md`.
- Terminology: *Identifier* (short *ID*), never "Handle" or "Identity". *Built In*, *Priority*, *Switch*, *Stop*, *Branch*.
- Changing an English string makes every translation of it stale and the game keeps showing the old one. Prefer a new key when
  the meaning changes; fix a typo knowingly.
- Keep `enUS` under 4096 entries (`learnings/tests-and-locales.md`).
- American spelling in English text, enforced by `tests/test_us_spelling.py`.
