# Offline compatibility checks

Run from the Rotation Master repository root:

`python3 tools/check` runs every suite below plus runner/vendor-integrity tests. It works from any directory when given an absolute path. `--static` runs Lua syntax, TOC/XML, pinned vendor integrity and literal localization checks. Prerequisites: Python 3, `lua5.1`, `luac5.1`, and `luajit` on PATH. CI runs the same command on pushes and pull requests.

The whole suite is green: `python3 tools/check_all.py` exits 0 with an empty `tools/known_failures.txt`. `check_all.py` runs the same commands as `tools/check` but reports every failure instead of stopping at the first; `tools/slow_tests.txt` lists the few commands worth leaving out of a quick local run (`--skip-slow`), with the durations measured at the last full run. `lua5.1 tests/default_corpus.lua` (every pack of every module on five synthetic client families) takes about half an hour on one core and is the slowest of them.

Locale suites. `client_locale.lua` loads the real AceLocale with the main catalog in `locales.xml` order for several game languages: only English and the game language stay resident, the main English table stays at or below 3,900 entries (the 4096 hash boundary), and it prints the resident memory. `text_bundles.lua` covers the load-on-demand text bundles (`Locales/bundles.json`, `Core/text_bundles.lua`): a normal start loads none, a bundle key loads exactly its own bundle once, the hash index owns every bundle key and no main key, every key reads as its translation in all ten languages, a bundle that cannot load answers with the key, and an unknown key reads as itself (the registration is silent). `test_locale_bundles.py` fails if any bundle string is missing, stale or invalid in any of the ten locales, if a key is in two catalogs, or if the index is stale. `test_locale_ids.py` covers the stable-ID formats, registry, reword (with a runtime mutation proof that nothing is orphaned), credits, notes and `locales.py where`; `test_migrate_locale_ids.py` the one-time converter. English files are generated, so suites read strings through `tests/fixtures/locale_entries.lua`. `locale_fallback.lua` covers AceLocale's own fallback to English. Fixtures that model the locale as one table load every catalog through `tests/fixtures/locale_files.lua`, and `f.language(name)` applies a game language to them.

`private_helper_identities.lua` records, for 64 Built In helpers on a Retail and a Burning Crusade client, the source hash that saved copies and exported bundles bind to (`builtin:<module>:<name>`). It is a living contract: when a helper changes on purpose, record the new hash there against the commit that changed it. Suites that rebuild a predecessor of a file (`tests/fixtures/restore_*.lua`) fail on any unrecorded edit of it by design; see `docs/dev/architecture.md`, "Tests", and prefer testing behavior to adding a byte-exact proof.

The repository includes an optional `.pre-commit-config.yaml`. If you already use pre-commit, add this local configuration through your existing hook setup; installation is deliberately not automatic. No global hooks or `core.hooksPath` are changed. CI remains authoritative.

`startup.lua` loads the real main module and extended-stat registration with a small WoW API fixture. It covers namespaced and legacy metadata, optional Classic threat tracking, extension initialization, spell-change events and the entering-world bag scan. With the real AceDB it also proves that boot prints no "Extra Field" warning for the one-time markers the migrations and seeders write (they are declared in the defaults as `false`, which reads like an absent marker, so an old profile is still migrated and seeded once). `questie_wiring.lua` covers main.lua's Questie wiring: one service, the late-load event owner only while the preference is on, and a re-sync after every profile replace, switch, copy, reset and import. `settings.lua` checks category IDs, parent registration and opening the configuration panel. `rangecheck.lua` loads the actual bundled range library and rejects the removed spell event. `aboutpanel.lua` builds the actual About panel for all 12 locale selections using Rotation Master metadata. `compression.lua` imports fixtures produced by the previous bundled LibCompress (90083) and checks default export round trips. `verify.py` parses every Lua file with Lua 5.1 and traverses the real TOC/XML dependency graph with exact filename case.

These checks do not run a WoW client. In TBC Anniversary 2.5.6, validate login/reload, `/rm config`, minimap clicks, rotation selection/highlighting, spell learning and item/bag changes. Full Forever compatibility is not established by these fixes; its spell, aura, talent and combat-data restrictions need separate client testing.

`buttons.lua` checks discovery and highlighting with modern button methods, legacy global helpers, explicit action attributes and absent optional frames. `button_providers.lua` builds fake frames shaped like each bar addon's buttons (EllesmereUI `EABButton` frames beside their hidden Blizzard twins, every `LibActionButton-1.0` variant, Dominos' two ID ranges and Blizzard-named frames, AzeriteUI6 pet buttons) and checks that discovery indexes the visible ones, that retired addons are no longer scanned, and the public `RegisterButtonProvider` API (validation, error containment, the 512-button bound, replace/unregister). `logging.lua` uses the real bundled AceDB shutdown to check late logging after defaults are removed, without writing defaults back into the saved profile.

`cache.lua` uses the real bundled CRC16 implementation to reproduce the former observation-key collision, then checks exact argument types/identity/arity, nil/false/void return arity, retry behavior, changed global callbacks, exceptions and unreadable/NaN argument bypass. Utility cache entries are ephemeral; `getCached` retains nil results, while `getRetryCached` retries void/all-nil results. Neither cache stringifies table arguments or creates entries for failed/retried observations. Table arguments use identity, so callers still own invalidation when mutable inputs change.

`item_sets.lua` checks the runtime item-set helpers independently of their former editor module: native/legacy identity and membership, fresh bag/equipped selection, priority, unavailable observations and profile/global shadowing. `startup.lua` also runs real binding normalization and unbinding against these helpers with native-only item APIs. This does not certify protected action behavior in the client.

`platform_inventory.lua` checks native/legacy count-only and full location snapshots through the same bag validation, including detached records and unavailable partial observations. `startup.lua` checks the extracted runtime snapshot's declared bag coverage, legacy slot compatibility, accurate locations, atomic publication and recovery. `bagContentsUnavailable` distinguishes a failed runtime scan from a successful empty snapshot; gameplay predicates still query the Platform boundary directly.

`builtin_modules.lua` simulates startup on TBC, Forever and Retail clients: exactly the character's load-on-demand class module (`Modules/RotationMaster_<Class>`) is requested, the modeled client picks its flavor TOC so only that edition's files run, and its packs register through `bind.lua`; every flavor TOC lists exactly its edition's blocks and packs, while a missing, disabled or failing module leaves Rotation Master working with one message. `default_corpus.lua` discovers every pack the module TOCs list and checks source/localization/schema/selection invariants across five synthetic families and thirteen class tokens, with sampled level/spec/build/action-context boundaries. Its helper is independent of combat evaluation; invalid-manifest probes test the guard itself. This is distinct from the real-predicate starter scenarios in `defaults.lua` and does not mean rotations exist for every tested class/client.

Reference-context regressions in `rotation_library.lua`, `rotation_catalog.lua`, `condition_engine.lua` and real-AceDB `startup.lua` check global/profile item-set precedence, dependency/schema removal and recovery, retained invalid packaged sources, strict custom writes and unchanged-lookups avoiding packaged-graph revalidation. These checks cover validation state, not live ownership or recommendation quality.

`defaults_tbc_mage.lua`, `defaults_tbc_warlock.lua` and `defaults_tbc_priest.lua` run each class's TBC premades through the real catalog, predicates, sequence executor and readiness: automatic selection between the class's premades and source variants at low, mid and maximum level, the casting/channel/target/pull Stops, single-target against engaged-enemy AoE branches, training stages and the independent reminders. Native observations are modeled.

Library source revisions, retained local widget forks and local vendor patches are recorded in `Libs/UPSTREAM.json`. The customized Spell/Item/ActionSlot Lua files are preserved. SharedMediaWidgets already matches current upstream; the Item EditBox upstream is unavailable.

`conditions.lua` runs real help callbacks and reproduces threat/outside-instance regressions. `condition_engine.lua` loads Core without AceGUI and checks Boolean compatibility, shared evaluation context, unavailable propagation and malformed/cyclic trees. `catalog.lua` loads the real TOC condition files and default categories for eight synthetic project/expansion/class/provider branches and invokes every registered help callback. These branch fixtures test declarations/help, not live compatibility with game products; These catalog branches still characterize inherited registration guards; product identity is tested separately by Platform fixtures.

`startup.lua` also checks combat-event policy: Retail, Forever and unknown clients do not register or process the thirteen raw combat/cast/nameplate observations, including direct callbacks with hostile payload/API traps. Reference metadata events remain active. Era/TBC/Progression synthetic probe clients retain registration and the existing cast/history scenarios. This is a callback-policy regression, not full client certification or a complete migration of every runtime API.

`platform_communication.lua` and `announcements.lua` check native/legacy chat selection, no retry after sender failure, public group/permission observations, destination policy, independent sound and chat, and unavailable optional media/audio APIs. Real `startup.lua` cast regressions cover native-only raid warnings, duplicate cast suppression and continued bookkeeping after output failures. These tests use mocked transports and do not send chat or certify server delivery.

`itemset_help.lua` checks whole-paragraph localization and both inherited item-set/list renderers. The native settings suite checks every current item-set input and collection action has authored help. These documentation guards do not establish secure macro/button support in a client.

`announcement_help.lua` checks whole-paragraph localization, all registered cast-event explanations, literal message substitutions, detached help records and legacy/native rendering compatibility. `settings_pages.lua` also checks the real Spell/Pet Spell/Item and chat/Audible field order and selector choices against authored announcement help. Other inherited help modules still contain untranslated prose; zero missing literal keys is not complete translation coverage.

`tools/catalog_check.py` lexes Lua strings/comments and checks literal `L["key"]` references against direct simple enUS assignments, including missing reads inside enUS itself. Equality comparisons and unassigned reads cannot mask missing definitions. Standalone invalid scalar literals and empty table/function values are rejected. Computed value types, nonempty constructors/functions, multiple-target assignments and dynamic/concatenated keys need review; this is not a full Lua parser or type checker. Long strings follow Lua opening-newline behavior. Untranslated raw prose and non-English coverage need separate review. `docs/quality/localization-inventory.json` tracks heuristic long raw-string candidates, including code snippets that need human classification; it is not a claim of complete extraction or finished translation. Regenerate intentionally with `python3 tools/catalog_check.py --inventory docs/quality/localization-inventory.json` after localization edits.

The condition evaluator now exposes `evaluateConditionResult` with `match`, `no-match` and `unavailable`; the existing `evaluateCondition` API returns true only for a match. Unknown/invalid conditions and unavailable descendants remain unavailable under AND/OR/NOT. A predicate can return `nil, reason` for unavailable observation data. Legacy nil without a reason remains false, preserving WoW Boolean API behavior. Inputs must be normalized readable values; this engine does not itself grant access to secret combat data. Full structured schema validation and callback diagnostics remain separate roadmap work.

`diagnostics.lua` tests bounded report capture, current-collector forwarding, preserved arguments/results, recursion protection and redacted versus explicitly requested original text. `errors_ui.lua` exercises the native report window without AceGUI. `/rm errors` opens the latest session report; select Copy and press Ctrl+C. Default redaction removes known roster/realm/guild names, player GUIDs and user-home paths and omits generated/custom Lua text. Review text before sharing: this is best-effort diagnostic redaction, not the future anonymized analytics export. Original details require an explicit button choice and reset to redacted on reopening. Reports are session-memory only and Clear affects only RM records, not BugJar.

Captured condition callbacks are quarantined until definition replacement or UI reload. Event/tick errors stop advice, clear previews/highlights and notify local consumers; after fixing the problem, reload to resume. Parse/bootstrap failures and callbacks outside RM's wrapped boundaries still use the normal client/collector path. The native copy window needs an in-game smoke check for scrolling, resize, copy, gameplay and collector coexistence.

`platform.lua` tests explicit five-family identity (plus historical progression IDs), independent build/expansion/ruleset facts, unknown projects, guarded values and API-declaration versus assisted-availability separation. Current evidence and missing in-game checks are in `docs/quality/client-support.md`; this metadata boundary is not a complete API port.

`platform_spells.lua` covers modern/legacy spell metadata and cooldown normalization, independent learned-state probes, player/pet banks and unreadable values. `platform_auras.lua` covers modern/legacy aura records, optional Era duration augmentation, per-field readability, permanent/expired timing and query failures. `aura_conditions.lua` runs the real buff/debuff predicates and headless engine, including own-caster upkeep, charges, numeric IDs and existing names, dispellable filtering, bounded scans, per-evaluation caching and unavailable propagation through NOT. These adapters do not yet migrate every spell consumer or establish live Retail/Forever recommendation support.

`custom_conditions.lua` checks that registration retains an independent nested field schema and carries the custom-code marker into diagnostic redaction. The inherited `addon.deepcopy` utility is a shallow filtered copy despite its name; this registration uses a separate recursive schema copy. Custom Lua remains user-authored executable code; this is not an import sandbox or completion of the custom editor overhaul.

Catalog checks now compare exact reviewed tag inventories for each branch, validate the documented primitive/union/nested field declaration grammar, and include MobInfo plus deferred ExtendedCharacterStats help/schema. `declaration_schema.lua` tests invalid, cyclic, deep and oversized declarations. This is an offline declaration guard; it is not the forthcoming nonmutating saved-rotation validator. `known_spell.lua` checks the adaptive SPELL_KNOWN predicate, including unlearned spells, player/pet banks, missing/restricted data, and editor callbacks independent of the spell dropdown loader.

`plain_data.lua` verifies bounded data-only traversal and independent copying without WoW/UI dependencies. `rotation_validation.lua` verifies the new envelope validator, dense ordered priorities, duplicate IDs, explicit applicability, structural condition checks and declared field types. Diagnostics are bounded and deterministic. Unknown fields/conditions/versions remain unchanged and unavailable for execution. `valid` means structural validity; semantic gameplay, current-client execution and recommendation quality remain explicitly unevaluated. The legacy repair/import path has not yet been replaced by these modules.

`rotation_catalog.lua` checks private copied built-ins, snapshot getters, always-listed disabled/withdrawn entries, owner-checked mutation APIs, fresh clone IDs, preserved baseline/origin mapping, clone-of-clone lineage, update independence and atomic collision failure. Built-in/custom references carry an explicit ownership kind to preserve both records if IDs collide. Malformed saved data is preserved and reported; getters do not expose its invalid metadata. The catalog now supplies packaged definitions to the live rotation library bridge and read-only browser; legacy custom bodies remain in their original per-spec store. Validation options and ID generators are trusted application dependencies, not imported rotation content.

`rotation_diff.lua` checks nonmutating field/nested edits and ID-based ordered add/remove/move comparisons. Clone origin maps suppress regenerated-ID noise; a longest increasing subsequence distinguishes moves from insertion shifts without a quadratic matrix. Outputs have explicit completeness limits. `CompareClone` consumes catalog views and returns baseline-to-source, baseline-to-custom and current-source-to-custom diffs; `conflictCoverage=field-edits` limits overlap highlighting to fields, while order changes stay visible in the three diffs. It performs no automatic merge. The temporary Compare rotations window exposes this service for saved custom/default targets and cloned-default three-way comparisons.

`rotation_library.lua` tests the live bridge: always-visible read-only pack views, explicit edition/class/spec/level/action-context eligibility, restricted-client reference policy, separate preferences, runtime key collision handling, profile rebinding, single saved clone body and retained lineage. Main startup tests additionally exercise default selection behind existing custom choices/fallbacks and clearing advice when a manual choice becomes unavailable. `defaults_ui.lua` checks the temporary browser's reference/enable/clone controls; it does not prove client layout/scrolling. `defaults.lua` checks the first shipped TBC Shaman 1–19 starter and real condition scenarios. See Modules/README.md for the module layout, source provenance, deliberate corpus gaps and live acceptance still required.

`rotation_comparison.lua` checks comparison direction, false values, whole added steps/unknown nested fields, bounded display, explicit clipping, markup escaping and read-only chooser/copy behavior. Library regression tests cover fresh-ID collisions against retained baselines and preservation of invalid-provenance errors. Ordinary duplicates keep minimal correspondence rather than fabricating a valid historical envelope.

`rotation_codec.lua` runs under LuaJIT with real AceSerializer/LibCompress. It checks old three-codec golden rotations and bounded new/legacy transport. See docs/quality/rotation-transport.md for exact limits and accepted formats. This module is not yet wired into the editor's import/apply flow.

`export_text.lua` (Lua 5.1 and LuaJIT) pins the export text rule and the whitespace-tolerant import normalization; `export_text_transfer.lua` (LuaJIT, real codec) round-trips every export kind through the wrapped string, checks corrupted-string errors and drives the transfer windows (fixed-pitch face, fallback, pasting). The rule is in docs/quality/export-text-format.md.

`item_presentation.lua` exercises the legacy item display consumers through the same protected display metadata boundary as the native picker: native-only name/icon data, intentional numeric-ID fields, delayed loading, stale-widget retry invalidation and malformed/restricted observations. `startup.lua` covers native item announcement links and literal percent characters. Actual picker/icon integration tests also retain exact duplicate-name identities and prevent retries touching a released/reused control or new text. Item condition/set icons use the same RM-owned drop/display implementation as spell icons, with item-specific validation; they no longer construct vendor ActionSlotItem. Display metadata deliberately does not require a minimum level; gameplay metadata retains that stricter contract.

The shared rotation canvas also has a compact tree/list presentation. Geometry tests preserve branch identities, False-before-True arm labels, typed insertion targets and forced/folded state with linear nesting width. Native editor tests use the same workspace, read-only rules, pending-field validation and Undo/Redo across view switches. The existing200-card rendering budget remains; virtualized larger lists remain separate work.

Rotation viewport tests cover independent25–200% content zoom, unscaled scroll-surface extents, center/clamp arithmetic, window-scale isolation, blank-space panning with pointer delta at effective window scale, card/field interaction guards, typed drop destinations after zoom, and stale/released interaction cancellation. For a local commit guard, run `python3 tools/install_hooks.py` to inspect the planned change, `python3 tools/install_hooks.py --install` to install, and `python3 tools/install_hooks.py --check` to verify it. The local pre-commit script runs `tools/check --static` before its existing shell body. It keeps a byte/mode-preserved original and installation record in the common Git hooks directory, preserves the hook's interpreter, path and arguments, and leaves `core.hooksPath` and personal/system dispatchers unchanged. Changed/unsupported/symlink hooks are refused for manual integration. Replacing an existing hook requires Linux atomic exchange; the actual displaced entry is retained and validated, with a detected concurrent change swapped back without deleting either version. Creating a new hook uses an exclusive hard link, so a concurrently created entry is never overwritten. An interrupted/refused installation retains its evidence for manual inspection. A previously non-executable hook stays inactive behind the project check; old branches without `tools/check` retain their prior hook behavior. Full behavioral checks still run through `python3 tools/check` and CI; the local hook covers syntax/load graph, translations and the pinned static checker.

`platform_macros.lua` and the actual button scanner cover current spell-ID and historical name/rank/ID macro spell observations, exact item/use-spell pairing, failed/missing/restricted observations, retry recovery and restricted-client query suppression. One unavailable macro is skipped while ordinary buttons remain discoverable. This resolves existing macro buttons at discovery time; it does not parse macro bodies, create/execute macros, certify castsequence/target refresh behavior or implement assigned-target buttons.

Explicit drag scope tests cover ordinary single-card moves into a following branch, Ctrl-drag sibling suffixes with branch ownership and one-step Undo/Redo, cycle/no-op rejection, and captured modifier state. Condition Ctrl-drag derives sibling paths rather than descendants; existing explicit selections still move together. Shared ordered settings/category roster moves preserve hidden following entries and manual arrows remain single-entry. Diagram rectangle selection and bulk actions remain pending design work.

Branch layout tests cover balanced arm roots with asymmetric subtree extents (including a21-card depth10 regression), straight populated arms with empty-side bypasses, independent arm folds and typed hidden-arm insertion slots, and bounds for arm label buttons. Native controls retain readonly viewing and stale callback guards. Shared drag previews expose separate counts and stack decoration; literal native icon references must resolve to owned TGA assets.

Condition prose tests run the real registry printer wrapper: explicit localized primary alternatives, positive direct calls, double negation, compound aura and nested spatial count comparisons, and balanced outer parentheses without precedence loss. Negation is presentation only; evaluation remains unchanged. See docs/architecture/condition-prose.md.

`bossmod_integration.lua` drives `Integrations/encounters.lua` with mocked DBM (`DBM:RegisterCallback` colon calls) and BigWigs (`BigWigsLoader.RegisterMessage` with a private owner) providers that follow the inspected contracts: encounter/stage/liveness, timer begin/update/pause/resume/stop with lazy expiry and a 64-timer bound, provider switching and detach, missing/unsupported/malformed providers, callback faults, the ADDON_LOADED lifecycle, the three BOSSMOD conditions (unavailable without a provider, also under NOT) and the one-time profile seed. It does not run DBM or BigWigs. `restore_bossmod_integration.lua` is the exact-bytes inverse that keeps closed historical fixtures running against their predecessors.

`defaults_forever_<class>.lua` (Druid, Hunter, Mage, Paladin, Priest) run the WoW Forever premades through the real catalog, predicates, composition, sequence executor, readiness and auto-select order on a modeled Forever client (`fixtures/forever_premade_model.lua`). RM never auto-selects a Built In on Forever's restricted policy, so scenarios use a synthetic Forever context with `probe` policy; each suite's last test keeps the real restricted policy and checks the premades are listed but not selected. They cover switches across levels and talent spells, priority order at early and full kits, Stop boundaries, single-target and AoE branches and reminders; they model the client, not native acceptance.

`defaults_retail_<class>.lua` (Death Knight, Demon Hunter, Druid, Evoker, Hunter, Mage, Monk) run the Retail premades through the real catalog, predicates, composition, sequence executor, readiness, Assisted Combat reader and auto-select order on a modeled Retail client (`fixtures/retail_premade_model_a.lua`, one specialization slot per fixture). `C_AssistedCombat` is modeled from Blizzard's generated API documentation; a secrets mode hides health, primary power, aura fields, enemy casts and cooldown times behind one sentinel while the never-secret cooldown flags, secondary resources and own casts stay readable. Scenarios use a synthetic `probe` policy; each suite's last test keeps the real restricted policy and checks the premades are listed but not selected.

`legacy_archive.lua` starts the real AceDB, `main.lua`, `init.lua` and the scoped store on a synthetic 1.4.3e SavedVariables table (`fixtures/legacy_143e_profile.lua`, which holds the older formats on purpose): every rotation lands in the unassigned archive and none is listed as running, every setting survives, the old formats (a cooldown effect stored by name, `pet` steps and `PETSPELL_*` conditions, rune names, bare item ids) are upgraded inside the archived bodies of every profile and character root and a second start changes nothing, the player is told once per profile and the banner follows the archive, bulk adoption goes through the single-record ownership code for the chosen scope (and reports a refused record without forcing it), and on the whole-poll fixture an adopted rotation is selected and advises its spell. `hostile_input.lua` pins what a stranger's paste may cost and write: a tag or an item list with a long run of spaces is trimmed in linear time (and an overlong tag is refused before it is trimmed), and an imported or saved item string never adds a line to the secure item-set macro (control characters are refused by the item-set import and the profile transfer, and removed with `;`, brackets and `|` at the macro itself). `legacy_archive_ui.lua` covers the Recover window's bulk buttons with their confirmation and the settings banner.

`rotation_specs.lua` covers a rotation's specializations (`body.specs`): the per-client classification (specialization IDs on Retail and Mists Classic, talent groups on Era, TBC, Wrath, Cataclysm and Forever at any level), eligibility from `body.specs` and never from the switch condition (a PvP switch stays in the minimap list), automatic switching specialization-then-switch-then-priority, the one-time profile migration of each recognized switch shape and the shapes it leaves alone, every converted premade against its pre-conversion switch (`fixtures/premade_spec_switches.lua`), exports dropping and imports filling in talent groups, the list's specialization dropdown and warning, and the editor's header picker. `lean_parity.lua` checks a talent-group restriction stops and resumes identically in both engines.

`tooltips.lua` covers the tooltip integration (`Core/tooltips.lua`, docs/architecture/tooltips.md) on the whole-poll fixture with fake tooltips and a fake data processor: the spell/item to rotation index (rotation and cooldown steps, disabled steps, branch arms, item sets and inline lists, conditions behind a setting, rank and base/override matching, priority and disabled ordering, the display-name helper), the item set index, the cap and "+N more", every toggle and the master switch, freshness (roster stamp throttle, dependency invalidation, specialization and profile, nothing built or read in combat or while disabled), both registration paths (mainline PostCall versus Classic scripts, including that the processor is not used where the tooltip is not built on it), callback guards (other tooltips, forbidden tooltips, unreadable or malformed IDs, a failing callback), and that the callback reads nothing from the tooltip. The General page controls, Apply and help text are in `settings_pages.lua`. No real client is involved.

`startup.lua` also covers the retired Simulator Format choice: a save from the 2.0 betas that still carries `profile.transfer_format` loads without a validator warning and drops the key, a profile exported with it still passes `ValidateProfileTransfer`, and the words someone might type for the removed feature (`/rm simulator`, `/rm import simulator`, ...) are one unknown-option warning each, never an error, with nothing in `/rm help` offering them.
