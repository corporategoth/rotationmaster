# Custom condition authoring

Conditions → Add or selecting a custom condition opens its editor in the right pane. The identifier is stable for an existing definition. Click the square icon to change it. The green Enabled pill beside Delete controls definition availability. The saved category appears with its icon after Description; click it to manage that category. The adjacent Move dropdown shows the pending destination, while the saved category remains unchanged until Apply. Function tabs select Evaluate, Validate, Summary, Fields UI, Help, On register and On unregister in one row. Callback description, typed arguments and return documentation precede Undo / Redo / Reset / Check syntax, then the signature and code. `addon` and `L` are available in each callback. Fields UI and Help use registered RM native controls. AceGUI controls, captured GUI library bindings and legacy module renderers are no longer supported; see [native UI migration](architecture/acegui-removal-boundaries.md).

The scrolling code field uses the bundled FAIAP indentation and syntax-color engine directly, with the bundled Inconsolata font. It returns uncolored source. A plain native editor remains available if syntax setup fails. Syntax colors, caret movement and native hit testing require client verification.

The source pane shares the rotation roster geometry and keeps metadata and footer actions fixed. Only code and schema viewports scroll. At compact heights, Help retains the full typed callback documentation. Field schema shows clickable field names/types, or an Edit fields link when empty. The graphical editor shows nested field/type cards. Records and alternatives contain their child cards; chevrons fold them. Left arrows reorder siblings, Duplicate copies the complete field, and the red trash deletes it. Drag into a highlighted gap to move between containers; Ctrl-drag carries following siblings, and containers always carry children. Live card previews restore their original positions on cancellation. Each card has help. New or copied names stay unique, and invalid fields have red borders. Undo/Redo, Apply and Cancel work on the schema draft. The Advanced checkbox switches to raw schema data. Invalid legacy schemas stay visible for repair.

Fields use a bounded data grammar, for example:

```
{ spell = { string, number }, unit = string, checks = condition[] }
```

Named tables are records; ordered tables are unions. Supported leaves are `string`, `number`, `boolean`, `condition` and `condition[]`. Nested unions/records are preserved. Legacy field names that are not identifiers are quoted, for example `["legacy-field"] = number`. Root fields may be empty; nested empty/mixed/sparse tables, duplicate names, cycles, unknown types and executable expressions are rejected. Parsing never evaluates Lua. The legacy Item Set schema literal remains readable and exports unchanged; compiled runtime declarations use the canonical table representation. The editable grammar is bounded to 16 levels, 512 parse nodes and 32 KiB of schema text. Existing saved definitions use a separate compatibility-loading policy, retaining generated UUID identifiers, long source/description values and legacy field names; normalized runtime schema traversal remains bounded. New callback bodies are limited to 64 KiB each and 256 KiB combined.

Edits stay in a detached draft. Each callback keeps its pending buffer and Undo/Redo history across tab changes and redraws. Reset restores its last saved code, or the template for a new condition, and can be undone. History retains at most 100 snapshots and 4 MiB. View Changes, Apply and Discard stay beside one another at the bottom of the pane. Leaving, Escape and right-click ask Apply/Discard/Cancel if there are pending edits. The schema editor temporarily owns the source actions; its fields and invalid raw input survive resizing. Page/profile replacement invalidates the editor and its child dialogs.

Check syntax compiles every callback but does not construct or invoke it. Success appears in green beside the footer actions; errors retain the warning color. Apply validates the complete definition, stages every callback, checks that the original definition/source still matches, then installs it. Source is saved only after successful registration. Failed compilation/registration preserves the prior registry entry and saved source. Registration errors enter `/rm errors` with custom source redacted by default and continue to the normal game error handler. Trusted Lua hooks may have external side effects that cannot be rolled back; this is not a sandbox or a proof of callback correctness.

The shared import/export dialog displays the source identifier, a replacement checkbox and new-copy name. Import requires an explicit trust confirmation and opens the imported definition in the draft. It does not register or save it until Apply.

## Native input troubleshooting

If the code field cannot place or move its cursor, reproduce the problem and run `/rm debug editor`. Copy that report to accompany the bug report. It contains native mouse/keyboard hit targets, source-editor identity, visibility, focus, cursor position, dimensions, font and bounded input-event counts/coordinates; it excludes the source text. Opening the report focuses its copyable text area, but collecting input state does not rewrite code, move the code cursor or take its focus. Plain text uses the same native input path and can help separate syntax-coloring problems from input problems. Fractional-size writes and unchanged native scroll offsets are guarded. The multiline input is anchored inside a stable backing scroll child, so RM no longer repeatedly assigns its text height. Caret placement and arrow navigation were confirmed working in TBC after this change.

## Optional editor provider contract

`RegisterLuaEditorProvider(name, create)` on the Rotation Master addon instance registers an optional provider factory. Obtain that instance with `LibStub("AceAddon-3.0"):GetAddon(actualInstalledAddonName)` or `_G[actualInstalledAddonName]`; the registered name follows the installation folder, including case. The factory receives `(parent, changed, valid)` and returns a controller with `frame`, `GetText()`, `SetText(text)` and `Release()`. `GetText()` returns plain Lua; `changed` signals edits; `valid()` is the owner's lifetime guard. Release must stop callbacks and release owned resources. Consumers explicitly request a provider through `CreateWorkbenchLuaEditor(parent, changed, valid, name)`; the normal editor defaults to the bundled native implementation. Failed creation, malformed controllers and runtime text-method errors fall back to native controls. No LuaWorkbench-specific API or automatic dependency is assumed.

CLASS_GROUP requires complete public roster observations on an identified client family. The current callback reads group membership, then the player and four party slots, or forty raid slots when raid inclusion selects a known raid. Known absent slots contribute zero; unavailable membership, existence or class facts keep the condition unavailable, including under NOT. Class filename strings are not restricted to a fixed enum, and current player identity is refreshed each evaluation pass. Historical saved raw CLASS_GROUP callbacks keep their original load-time class binding and its packaged requirement identity.
