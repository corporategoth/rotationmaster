# Legacy elapsed-time profiling

The legacy profiler is the small `ProfiledCode` object created during normal addon initialization. The evaluator keeps the same root and environment/rotation/cooldown child start/stop calls. Every fifteen seconds main logs `report(detailed_profiling)` through `debug`, then resets the window. Debug output is displayed only at log level 3 or higher. The Detailed Profiling checkbox controls whether child summaries appear; it does not control collection. This change does not alter those policies or main.lua.

The clock is selected once when a profiler is constructed: `GetTimePreciseSec`, otherwise `debugprofilestop`, otherwise `GetTime`. The first two provide continuous timing within a frame. `GetTime` can remain constant throughout one frame, so its fallback is explicitly labelled coarse. The shared debug profiling clock is never reset. Its backwards jumps, failures, and nonfinite results discard that span as unavailable instead of polluting accumulated times. A missing clock is also unavailable, rather than a fabricated zero.

Reports show count, total, minimum, average, and maximum in milliseconds with three decimal places. Existing public numeric `total`, `min`, `max`, and `startTime` remain in seconds. For example a three-microsecond span displays `0.003 ms`. Reset still clears the accumulated window and children; child getters remain stable until reset. Default `ProfiledCode()` and explicit `true` preserve unconditional collection. Optional explicit `ProfiledCode(false)` returns a clock-free no-op object whose child chains return itself.

These are inclusive elapsed scopes, not native per-addon CPU counters. Nested children can overlap and their values must not be added to the root. The root begins after rotation preparation and excludes unrelated events/rendering. GC or synchronous callbacks can contribute to elapsed time. The modern native CPU/runtime reports and their phase-marker child lookups are unchanged.
