# Legacy elapsed-time profiling

Main uses clock-free no-op profiling at Default and Silent log levels. Debug and Verbose collect the legacy elapsed-time scopes and log them every fifteen seconds. The Detailed Profiling checkbox controls child summaries. The six environment/rotation/cooldown child lookups remain for native capture phase markers. Changing the log level takes effect on Apply, and profile refreshes update the policy. An active native capture or a customized profiler is preserved; an owned profiler can switch modes after the capture restores its methods.

The clock is selected once when a profiler is constructed: `GetTimePreciseSec`, otherwise `debugprofilestop`, otherwise `GetTime`. The first two provide continuous timing within a frame. `GetTime` can remain constant throughout one frame, so its fallback cannot resolve work within that frame. The shared debug profiling clock is never reset. Its backwards jumps, failures, and nonfinite results discard that span as unavailable instead of polluting accumulated times. A missing clock is also unavailable, rather than a fabricated zero.

Reports show count, total, minimum, average, and maximum in milliseconds with three decimal places. Existing public numeric `total`, `min`, `max`, and `startTime` remain in seconds. For example a three-microsecond span displays `0.003 ms`. Reset still clears the accumulated window and children; child getters remain stable until reset. Default `ProfiledCode()` and explicit `true` preserve unconditional collection. Optional explicit `ProfiledCode(false)` returns a clock-free no-op object whose child chains return itself.

These are inclusive elapsed scopes, not native per-addon CPU counters. Nested children can overlap and their values must not be added to the root. The root begins after rotation preparation and excludes unrelated events/rendering. Main’s named children cover unit/spell/combat-history environment work, the rotation decision, and all optional cooldown rows. The parent also measures macro refresh, damage-history cleanup, readiness construction, source checks, and publication outside those children. That parent work explains the gap between the root total and its child totals; a cooldown child is one scope per evaluation, regardless of how many configured cooldown rows it visits. GC or synchronous callbacks can contribute to elapsed time. The modern native CPU/runtime reports and their phase-marker child lookups are unchanged.
