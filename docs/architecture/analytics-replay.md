# Normalized analytics replay foundation

`addon.Analytics.Replay(trace)` is a pure dot-call reducer for caller-normalized version-1 TBC/player evidence. It does not collect events, start sessions, call the recommendation engine or native APIs, save data, expose capture controls or certify native visibility/adherence. Loading the module installs no event subscriptions or timers. A future collector must separately prove its observation and presentation contracts before producing live scores.

The input header is `{format=1, model=1, family="tbc", actor="player", duration=seconds, records=rows}`. Every row has a strictly increasing integer `seq`, nondecreasing finite `time` within the capture duration, and a fixed `type` schema. Supported types are advice, presentation, retire, attempt, result, damage and damageCoverage. Unknown fields, unsafe tables, malformed ordering and resource-limit failures return a bounded unavailable report without a misleading partial score. The implementation and tests define the exact fields/enums; arbitrary strings, raw GUIDs, names and executable values are not accepted.

Advice includes a numeric epoch, an action classification and (for a spell) its exact ID and expiration. Presentation acknowledges only an earlier current advice sequence. An ordinary player attempt freezes the latest acknowledged, same-epoch spell advice strictly before expiration. Subsequent advice or acknowledgements cannot rescue an unobserved attempt. Retirement/epoch changes make pending attempts unobservable. Results must preserve the attempt identity. Successful ordinary casts are classified as exact matches, different/unmodeled or unobservable; repeated polls, failed casts, channels, pets and duplicate aliases do not create scorable opportunities. Different does not mean incorrect. No observations means unavailable.

Damage is player-only across explicit available-coverage intervals, with four normalized subtype classifications. Readable zero differs from no event; unknown actors, fields, unsupported subtypes and coverage gaps remain visible. Raw logged amount and optional overkill-adjusted amount have separate availability. Rates use covered capture seconds, never invented encounter duration. Pet-inclusive, recipient, role, latency, alternative-action, intent and quality conclusions remain unavailable.

Bounds are 600 seconds, 4,096 records, 1,024 distinct cast aliases, 128 pending casts, 30-second pending age and a 512-KiB deterministic payload charge. The charge is a validation budget, not a precise Lua heap or wire size. Inputs remain unchanged and reports are detached and contain no input aliases or source text. Both Lua runtimes test frozen associations, expiration, retirement, duplicate/conflicting results, partial damage coverage, overflow and every cap.

Live capture/UI, native tuple validation, presentation acknowledgement and role-specific comparisons remain separate pending work. The pure replay foundation does not complete those features.

## Bounded capture builder

`addon.Analytics.NewCapture(options)` creates an in-memory builder for trusted, caller-normalized receipts. Its colon methods are `Start`, `Push`, `Stop`, `Clear` and `GetSnapshot`. `Start` returns a session lease; stale or foreign leases cannot publish evidence. `Push` accepts advice, presentation, retirement, attempt and result receipts. It assigns elapsed times and sequence numbers, keeps raw cast keys private and emits detached numeric aliases. The optional advice maximum age defaults to 0.5 seconds.

`Stop` retires the session before passing its detached trace to Replay. Pending casts remain conservative; later channel or autorepeat classification excludes the entire alias. No provisional score is returned while a capture is active. The final report explicitly states `collection="not-wired"` and does not certify native evidence.

The builder applies the replay duration, row, alias, pending-count and pending-age limits, plus a deterministic 512-KiB payload budget including private keys. Exceeding a limit produces an unavailable report rather than a partial percentage. It installs no event subscriptions, timers, producers, saved data or capture UI. Native tuple validation, active-rotation epochs, presentation acknowledgements and live capture remain pending integration work.
