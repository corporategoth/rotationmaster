# Editor feedback and tags

RM editor cards use a separate amber rail for unsaved changes. Red/green/gray borders retain their validation, negation and reachability meanings. Rotation sessions expose detached baselines; a step compares both its data and structural location, and a changed descendant also marks its branch. Condition cards compare semantic nodes at their paths. Native settings use saved draft baselines, pending input values and collection identities; Apply, Discard and history redraw the markers. Custom Lua callbacks and metadata fields have their own field markers. Opening a read-only definition is not a change.

Dragging temporarily moves RM-owned rendered cards or rows into a floating overlay at their current scale and spacing. Gray placeholders stay in their original parents. Internal connector lines are copied into the overlay. Cancel, Escape, drop, rerender and release restore original parents, anchors, levels and strata before applying a data command. Source palette controls use the same presentation. Ordinary dragging carries one entry and its children; Ctrl at drag start carries its following siblings too. Branches and condition groups always carry their own subtrees. Hidden descendants remain part of the data move even when they have no rendered preview frame. Native pointer/clipping behavior still requires client acceptance.

Metadata and roster filters share `UI/tag_picker.lua`: type to find existing labels, click suggestions, and remove selected pill chips. Metadata also accepts a new valid tag on Enter. Filters select existing labels only, with an Any/All pill; an empty selection matches everything. Tags remain rotation data. Optional RGBA tag colors live in a case-insensitive profile palette (`rotationTagColors`), default white, and travel in profile exports. Right-click a pill to choose its color. The color picker's own Use/Cancel lifecycle applies independently of a rotation metadata draft.

Switch priority is an integer from -100000 to 100000, with minus/input/plus controls and blank meaning zero. Incomplete minus input remains unsaved and cannot be applied. Metadata sources display rotation guides; per-spell/item research remains in development evidence. Existing imported provenance is preserved, even when an entity URL is hidden from this summary.

All collection sidebars reserve their own footer space independently of the details pane's Apply/Cancel row. Search is first, followed by category or tag filters. Shared selectors fit the filtered result count, use the anchor width and compact contiguous rows, and scroll when there are more than ten matches. Typed integer sliders reject fractions; dragging integer settings rounds to their declared step.


## Draft comparisons and preview

View Changes sits beside Apply on rotation, condition, metadata, custom-code and native settings editors. It uses the same two-column comparison window with Saved and Unsaved headings; unchanged rows are hidden by default. Comparisons read detached snapshots and raw pending input without flushing widgets, executing custom Lua, saving data or creating undo history. Invalid pending input is shown separately. The button is disabled for clean and read-only drafts. Windows close when their owner becomes invalid. Condition comparisons are bounded to 512 nodes per side and explicitly report truncation.

The native recommendation preview pools square icon buttons instead of allocating AceGUI widgets on the runtime path. It has a compact header and close control with no footer. Profile settings persist count (integer 0–5), horizontal/vertical direction, lock, background opacity, icon size and position. Opacity zero hides chrome without fading icons or intercepting blank-space clicks. Resize maintains a count/direction-based ratio; General Reset restores centered 64-pixel icons. General places opacity above equal-width Lock, Direction and Reset controls. Real WoW resize, hit-testing and tooltip appearance require client acceptance.

Condition sidebars show search first, dedicated All / Built In / Custom source buttons, then category selection. Add and Import/Export share the footer above Manage categories; transfer is disabled for built-in definitions and custom imports enter the existing trusted-code review flow. Search boxes use an in-field hint that disappears while focused or populated. Selected dropdown entries retain their icons.

Preview Reset now applies position/icon-size immediately, synchronizing just those saved/draft baselines while preserving other pending settings. Straight branch-arm labels center on the other arm's horizontal split. View Changes is a text-only peer of Apply/Cancel.

Native Lua inputs explicitly receive mouse focus. Callback tabs preserve raw invalid metadata and current source instead of flushing the whole form. Source reads bypass the bundled highlighter's deferred cache. The Integrations tab stages a profile editor choice (Automatic, bundled highlighting, plain text, or registered provider); a failing provider falls back explicitly to native rather than recursively reselecting itself. The LuaWorkbench adapter embeds pinned upstream components in an independent RM-owned namespace; see [the advanced editing contract](condition-authoring.md#optional-advanced-editing). It supplies editing, API knowledge, completion, navigation and debugging without borrowing the user's Workspace or requiring upstream changes. Native input, code rendering and line-number navigation have been accepted in game for both providers.

Directly reported RM warnings, including AceLocale missing entries, are observed through a chained error handler. Every message still reaches the prior collector; unrelated stacks are forwarded without local recording, and the observer's own stack frame does not establish RM ownership. Normal caught exceptions are not captured twice. Each RM boundary checks for a newer collector and preserves it in the chain. This requires geterrorhandler/seterrorhandler; older/minimal environments without them keep the original boundary-only diagnostics.
