# Rotation content and dependency revisions

A saved custom rotation body can contain a readonly positive integer `revision`. Legacy bodies without this member have logical revision 1; reading or opening them does not write the member. New rotations and copies start at 1. A committed content or ownership change increments the canonical saved count once. Unsaved commands, discard, failed commits and semantic no-op Apply do not increment it. Editing the draft count cannot choose the next revision.

This counter records no history. It is distinct from the source envelope revision, packaged source revision and comparison provenance. New imports retain a valid incoming body revision; replacing a local rotation increments its local revision. Profile transfer, ordinary serialization and repair preserve valid saved values. Invalid or exhausted counts reject publication. Only the body's own revision is excluded from semantic dirty comparison; nested user fields named `revision` remain content, and concurrency checks retain the complete canonical record.

The dependency service starts immediately after `globals.lua`, before dependency writers capture its notification function. It maintains a private monotonic generation and an opaque non-repeating stamp. The real addon owner uses that generation together with root identities to check unchanged dependency maps without traversing their entries. Normal AceDB default metatables do not disable this path. Public validation options remain fresh detached maps, rather than retained private projections. These map copies are shallow: table-valued entries still refer to canonical dependency objects, so changing those objects also requires notification.

Controlled commits notify after publishing canonical state and before subsequent user callbacks or reentrant selection. Registration, removal, availability changes, failed-registration rollback, function bundles, itemsets, effects, profile replacement, repair and migrations all participate. Rollback advances freshness; it never reinstates an earlier stamp. Unsaved draft edits do not notify.

Third-party code that directly changes a managed dependency in place must notify before returning to evaluation or invoking reentrant addon work:

```lua
rotationmaster:InvalidateRotationDependencies('condition', conditionId)
rotationmaster:InvalidateRotationDependencies('function', functionId)
rotationmaster:InvalidateRotationDependencies('itemset', itemsetId)
rotationmaster:InvalidateRotationDependencies('effect', effectId)
-- Bulk or otherwise unclassified canonical changes:
rotationmaster:InvalidateRotationDependencies('all')
```

An unnotified in-place write is outside this managed contract. Replacing an observed root still changes freshness. Foreign receivers or loaders without the private startup capability retain the scanner compatibility path. Public callback overrides retain their dispatch and error behavior.

After a final full execution proof, prepared managed publication may use a compact notification lease only for already-computed scalar output and detached presentation views. Official edits, dependency notifications, profile/rebind operations and public mutable-asset exposure or borrowing retire that invocation before returning to callbacks. Direct database/profile or selected spec/key changes still retire it immediately. Unnotified nested Store/dependency-root or metatable changes need not stop this finished ordinary-delivery phase; full admission observes root changes before the next execution. External Store structure changes still require explicit Refresh. A later private-node handoff outside the admitted source-owned executor, including an availability announcement, retains a full proof immediately before the handoff. Unnotified in-place content edits do not gain a promise of eventual deep detection. Ordinary/custom evaluation, callback dispatch, errors and publication cadence retain their existing contracts.

Admitted managed execution may also use the notification continuation between reached condition callbacks after full acquisition. A cached completed planGeneration skips only the preliminary prior-plan authority check when the execution generation is unchanged; each acquisition still performs the fresh full Scope entry proof, and staged delivery still requires the final full publication proof. Final Prepare admission and the post-environment boundary use that continuation together with the existing engine/provider authority checks, rather than repeating Store/dependency-root validation. The private body remains immutable and does not escape into public/custom callbacks. Actual condition, helper, step and sequence consumers retain finite source identity/environment certificates at their input handoffs, including after the Diagnostics observer and before its inner callback. Request/plan/generation, database/profile/spec/selection ownership, quarantine and event epochs still retire stale work immediately; rejected continuations latch the invocation and cannot retire a newer nested session. Official mutations and public selected-asset exposure or borrowing must notify before returning. Unnotified nested Store/dependency-root or metatable changes need not stop that already admitted invocation and are checked at the next full acquisition; this does not promise deep detection of unnotified in-place content edits. Full acquisition through active-plan authority and Scope entry, the final full proof before staged output and a full proof immediately before rare availability-announcement handback remain. An explicit full-proof request still uses the retained full guard. Five-argument callers and unqualified, custom or public override routes keep their original full-proof/dispatch/error behavior. This changes no volatile observation, fact-cache lifetime, callback order or polling cadence.

Activation and retirement now pass through one runtime service before selection, publication or cleanup. It reserves an operation token before resolving the selected record, so a reentrant newer selection wins. The private activation identity changes for a different profile, spec, address or committed body; a same-selection no-op keeps its identity. Save and import writers prepare the private handoff before their final authority checks and finish it without extension callbacks after successful publication. Cleanup retains only the retired spec and visible ID while the operation remains current. New activation expires that cleanup context. Profile/archive adoption and an explicit store rebind preserve an existing exact selection through its new coordinator key; the Default alias deliberately follows its effective owner. A reentrant newer switch or bind takes precedence over every older continuation. The new transition controls are captured by their consumers at module load; existing public callback overrides retain guarded live dispatch. This state is runtime-only; it adds no saved history or cross-poll gameplay cache.

This checkpoint uses one aggregate dependency generation. The identity parameters describe cold publications; they do not yet select only the active rotation's dependencies. The next refinement will keep a generated dependency set and volatile dependency revision alongside the active rotation ID, rebuild that state at activation, and distinguish active freshness from inactive catalog validation. Dependency sets and runtime generations are not saved in rotation bodies or exported. Persistent metadata for individually editable dependencies is a separate remaining task.

These revisions cache authoring validity. Casts, channels, cooldowns, range, combat relationships and other changing gameplay facts retain their current polling and per-evaluation observation rules. No cross-poll gameplay result cache is introduced here. Native CPU improvement must be measured after deployment; the offline proof establishes zero dependency-map walks on unchanged managed stamp reads, not a promised CPU percentage.

The optional CPU capture appends six fixed runtime-work views: store plain/field/address checks, the warm unit-update helper, the diagnostic call boundary and the selected phase-profiler child method. Source-local handoffs expose only captured function references at capture boundaries; measured helpers are never invoked by collection. Counters share the existing bounded sample pool, add at most24 native queries per completed capture, preserve prior report/ranking/query order and add no polling work. Object/function replacement, missing services, cancellation and stale capture ownership make rows unavailable. These overlapping native scopes identify further candidates; they do not establish another optimization or a partition of addon CPU.
