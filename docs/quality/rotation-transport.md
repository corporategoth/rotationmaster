# Rotation transport contract

`Data/codec.lua` is a data-only boundary with injected trusted serializer/compressor functions. Runtime wiring/import staging is the next step; the old editor import path is not upgraded merely by loading this module.

Legacy data uses standard Base64 of a LibCompress stream containing AceSerializer protocol1. Accepted compression bytes are exactly1 (stored),2 (LZW),3 (Huffman), without modern prefilters. New envelopes use the same payload with `RM1:` before the Base64; this is a transport version, distinct from the envelope's `schemaVersion`. Unknown content schema versions remain decoded data for validation/reference. Native Deflate/Zlib/Gzip and filtered streams are explicitly unsupported here because their output limits have not been established. Exports request LibCompress capability1. No vendor code or hashes were changed.

Limits: original pasted text2MiB; compressed payload1MiB+1; serialized output1MiB; serializer control tokens20,000 and table depth64. Portable-data traversal adds its independent depth/node/string/byte constraints. An otherwise portable object can exceed the serializer transport limit after escaping; export returns an explicit size error. Wrapping and invisible copy artifacts are accepted, including around the marker; the exact presentation and import rule is in `export-text-format.md`. Junk alphabet, misplaced padding and nonzero unused Base64 tail bits are rejected.

Before decompression, stored length is checked, LZW output size is calculated using dictionary lengths only, and Huffman's 24-bit output length plus symbol-codebook shape are bounded. Escaped codes must terminate within 32 bits plus their stop bits, preventing the library's unbounded malformed-map scan. Invalid/truncated LZW codes are rejected before entering LibCompress. Actual decompression remains the bundled library's job. Its result must match the expected length. Before AceSerializer's recursive parser runs, the structural token stream must contain exactly one root table and stay within depth/token limits. The same serializer preflight runs during export, so an accepted export cannot exceed the importer's depth/token contract. Parsed data is then checked for finite, portable values. Errors return stable codes; no predicates/custom Lua are executed or registered and no SavedVariables are modified.

This is not JSON or LibDeflate. Numeric keys, Boolean false, Unicode bytes and priority ordering survive the actual codec. The original pasted string is retained with each decoded session result. Compression/decompression functions are trusted dependencies, rather than imported data. The codec does not establish condition semantics, applicability or recommendation quality; the validator and explicit import-apply boundary handle those concerns.

`tests/fixtures/legacy_rotation_exports.lua` contains Store/LZW/Huffman golden rotations produced with Rotation Master's original bundled LibCompress90083 (2018 revision83), using AceSerializer protocol1. The untouched backup used to produce them remains in the thread's work/library-backup. The fixtures also give the future website a fixed compatibility target. `tests/rotation_codec.lua` uses the actual current vendored libraries in LuaJIT for golden decode, envelope/legacy roundtrips, numeric priority order, Unicode/false, malformed transport, expansion/depth/token limits and checking that rejected streams never reach expensive parser/decompressor callbacks.


## Staged import boundary

The editor uses the bounded codec only after **Preview import**, rather than decompressing while typing. A session candidate retains the original text, detached decoded data and pure validation. Editing text invalidates the candidate token. Legacy bodies are validated with `ValidateBody`, without inventing an edition/class scope; declared envelope scope remains intact. Invalid, unsupported and unresolved candidates can be inspected, but cannot be applied. Preview rendering does not evaluate conditions or invoke installed custom Lua print callbacks, including nested custom conditions; those use a bounded data-only description. **Inspect import** includes envelope metadata, unknown fields and validation diagnostics in a bounded copyable report; display truncation is explicit and the original transport text remains available.

**Import as new rotation** creates an independent editable copy with fresh rotation/step IDs. It never replaces the selected custom rotation or a packaged default. Allocation/copy/validation complete before committing the body. Invalid destination containers are preserved and refused. Envelope imports keep one saved body in the legacy rotations table and a body-free manifest plus correspondence in `rotationLibrary.imports`; edition/class/level/context selection, duplication and export preserve this metadata. Import correspondence provides two-way step pairing without fabricating a historical default baseline. Existing default clones retain their local baseline independently; importing an exported envelope does not reconstruct baseline history that the export did not contain.

Legacy custom bodies export in the original unmarked transport. Packaged defaults, their sourced clones and imported envelopes export as `RM1:` envelopes, retaining their scope and sources. An older RM version cannot interpret that envelope. This boundary does not automatically merge changes, validate rotation quality or certify live client behavior.

**Names of Built Ins.** A packaged default's envelope names itself by `nameKey`, a locale key (`Default.<Edition>.<Class>.<Variant>.Name`), and the key stays in the export because it is what the envelope is. A key is never a name: the export also carries `body.name`, the display name in the exporting client's language (`addon:RotationDisplayName`, `Core/rotation_library.lua`), and the importer shows `body.name`, else `nameKey`. An older export holds only the key; it is resolved through the importing client's locale, and a key that client has no text for reads as its variant ("Feral No Such Tavern Casual"), never as the dotted key. Only a registered `Default.*.Name` key is ever resolved, and the locale table is read raw (AceLocale reports a missing key), so a user's own name is left as typed, even when it looks like a key or is another locale key. A user name that is exactly a registered `Default.*.Name` key (what importing a key-named export stored before this) shows as the display name in the transfer and comparison windows and exports as it (the Rotations list still shows the stored text until renamed). `tests/rotation_name_transfer.lua` covers English, German and untranslated for every shipped Built In.

Optional `body.tags` is a bounded dense list of tag strings. It overrides envelope tags, including an explicit empty list; absent body tags inherit the retained envelope tags. Current source exports synchronize their envelope tags on a copy while retaining historical provenance untouched. Both representations are validated. Tags support64 UTF-8 codepoints each,64 entries, no control characters or malformed UTF-8. UI CSV parsing is bounded to32 KiB; quoted commas and escaped quotes roundtrip as data, without evaluation.

Optional `body.priority` is an integer in [-100000,100000]; absent means zero. It survives clone/import/export/reload and shares metadata draft history. It orders candidates within an ownership class only; user custom/fallback precedence over packaged recommendations is unchanged.
