# Settings workbench

The built-in General, Conditions, Effects, Item Sets, Announces, Profiles and About tabs now use RM-owned native forms. They share flat fields, left-hand labels, compact checkboxes and sliders, searchable selectors, collapsible sections and the workbench scrollbar. Existing saved data formats remain in place. Optional module tabs keep the module’s renderer.

Settings on these tabs apply immediately. Text commits on Enter or when its field loses focus. Invalid text stays red and blocks switching tabs or closing the window; Escape restores that field’s last committed text. Checkbox, selector and button actions flush valid text before proceeding. Profiles bracket changes with recommendation disable/enable and explicitly confirm Copy, Reset and Delete.

General retains polling, switching, minimap, bar highlighting, history, preview, profile effect defaults, specialization names where applicable, and debugging options. Its effect preview is removed when leaving the page. Color channels display three decimals on the0–1 scale; opening a field never rewrites its stored precision. General uses two columns with whole categories kept together; Disable Auto-Switching and Disable Bar Highlighting share a row. Position combines Anchor on the left, a shared tightly packed directional pad, and V/H offsets. All native settings, cooldown magnification, window scale and color-picker sliders have editable numeric values.

Conditions manages categories and their ordering, hidden types, switch-condition availability and custom definitions. Conditions, Effects, Item Sets and Announces use a searchable left roster with details on the right. Conditions also has a category filter and condition icons. Collection search does not discard or redraw pending detail edits. The custom Lua authoring window remains the existing explicit adapter; it uses a detached copy and refuses Save after its owning native page is gone. Replacing that authoring window with the native/editor-provider design remains pending.

Effects selects one effect at a time, exposes type-specific fields and native sequence editing, and supports duplication, deletion and validated import/export. Opening an effect does not fill in or change its stored defaults. A type change or creation can initialize the selected type’s settings. Item Sets keeps priority order, global/profile scope, action bar binding, packaged reset and newline/comma-separated transfer. Announcements expose action, exact rank, event, channel, text, participation and deletion. Spell and item fields share provider-based search, names/icons, exact IDs behind the display, and scope filtering. Numeric values loaded by old condition declarations (including Buff Present) are normalized centrally; uncached items retain their identity while showing a loading label. Item actions and announcements retain custom lists or item-set references. Condition dropdowns use the native searchable selector, outside scroll clipping, with Escape/click-outside cancellation. AceGUI still bridges legacy field layout; the UI dependency has not yet been removed.

Help is a compact formatted native article with the same chrome, Help at the top right, X/Escape/right-click closure, and no report-copy or extra Close controls. Main-window Help includes the authored field documentation. General fields follow the same order as the page, without separate question marks beside controls. The authored text is shared data used by both renderers. Rotation/cooldown/branch Help describes clickable elements and drag/edit behavior. A condition card’s summary Help explains its interactions; with fields open, Help appends that condition’s specific help beneath those fields. Diagnostic and full-expression copy dialogs remain separate.

Remaining UI migration: custom Lua authoring/provider integration, existing legacy condition-specific field declarations and their specialized child dialogs, runtime preview window styling, plus optional module-owned pages. Native WoW font wrapping, clipping, popup focus/stacking, sound and protected-client behavior still require in-game checks. The offline fixtures verify data and callback ownership; they do not render the game.


Effects sequences now share ordered native cards for Animate, Pulse, Dazzle and Custom. Item Set entries use compact table rows with the same Up/Down boundary rules, drag ghost, insertion gaps and right-hand Trash. Drag a card header or an item row’s grip; editing text remains ordinary text selection. Invalid pending text blocks reordering/deletion. Redraw, navigation and profile replacement cancel owned drags.

Effects and Item Sets have a two-by-two New/Duplicate/Import-Export/Compare footer below their lists. Compare excludes the selected entry, shows human labels and icons in two columns, hides unchanged fields by default, and is read-only. Root Delete is red and right-aligned. The effect preview spans Name/Type rather than consuming a separate row. Announcement creation has a single Add action in the roster footer, with direct fields and no collapsible creation heading.
